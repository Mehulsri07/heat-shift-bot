# Heat-safe shift planner (name TBD)

An Android app that tells a construction-site supervisor which hours are safe for outdoor work in extreme heat, and turns the plan into a Hindi voice note for the crew.

Team OpusCube's entry for the WeMakeDevs x AWS environmental hackathon, Heat and Water track.

## The problem

Outdoor workers in Rajasthan keep working through dangerous afternoon heat because nobody turns the weather forecast into a shift decision. Heat forecasts exist; site-level instructions don't.

## Who it is for

- **The site supervisor.** One supervisor sets shift timing for a whole crew. They set up their site once in the app and get an hour-by-hour plan.
- **The workers.** They get the plan as a short Hindi voice note, shared by the supervisor to the crew's WhatsApp group. No app, no reading.

## How it works

```
Android app and web link (one React codebase)
        |
Amazon CloudFront (one HTTPS domain)
        |-- app files --> Amazon S3 (web build and APK download)
        |-- /api/* ----> API Gateway + api Lambda --> Amazon DynamoDB
                                |  async
                                v
EventBridge Scheduler --> planner Lambda (Strands agent + risk engine) --> DynamoDB
     (06:00 IST)                |
                                |--> Open-Meteo (hourly forecast)
                                |--> Amazon Bedrock (Claude Haiku)
                                |--> Amazon Polly (Hindi voice, MP3)
                                |--> Amazon S3 (voice note files)
```

1. The app is a React UI, shipped as an Android APK (wrapped with Capacitor) and as a web link. Both call the same JSON API.
2. The `api` Lambda validates the request, saves it, and hands plan building to the `planner` Lambda in the background. The app polls until the plan is ready.
3. `planner` runs a Strands agent on Amazon Bedrock. The agent fetches the hourly forecast from Open-Meteo and passes it to the risk engine.
4. The risk engine (`src/risk.py`) is plain, tested Python: NWS heat index plus IMD air-temperature cut-offs give each hour one of five bands. **The model never decides a band, a temperature or a time; it only words what the engine returns.** A guard checks every number in the model's text against the engine output and falls back to a template if any number was invented.
5. On request, Amazon Polly turns the plan into a Hindi voice note that the supervisor shares from the app.
6. On dangerous days the plan carries a fixed, human-reviewed heat-stroke warning. The API attaches it from a file; it is never generated by the model.

## AWS services and open source

| Service | Used for |
|---|---|
| Strands Agents SDK (AWS open source) | Agent framework and tool calling |
| AWS SAM CLI (AWS open source) | Infrastructure as code, build and deploy |
| AWS Lambda | `api` and `planner` functions |
| Amazon API Gateway (HTTP API) | The JSON API under `/api` |
| Amazon CloudFront | One HTTPS domain for the app, the APK download and the API |
| Amazon Bedrock | Claude Haiku, writes the plan text |
| Amazon Polly | Hindi voice note (voice Kajal, neural) |
| Amazon DynamoDB | Sites, plans and cooling points |
| Amazon S3 | The web build and APK; generated voice notes |
| Amazon EventBridge Scheduler | Daily 06:00 IST plan refresh |
| Amazon CloudWatch Logs | Logs |

## Setup

Prerequisites: Python 3.11+, AWS CLI v2, SAM CLI, Docker (the backend build runs in a container), and an AWS account with Bedrock access to Claude Haiku in `us-east-1`. For the app: Node.js and Android Studio.

### Backend

```bash
pip install -r requirements.txt
pytest
```

```bash
sam build
sam deploy --parameter-overrides BedrockModelId=<Claude Haiku model or inference profile ID>
```

The deploy prints four outputs: `AppUrl`, `WebBucketName`, `DistributionId` and `CoolingTable`.

### Web build

```bash
npm --prefix web install
npm --prefix web run build
aws s3 sync web/dist s3://<WebBucketName> --delete --exclude "download/*"
aws cloudfront create-invalidation --distribution-id <DistributionId> --paths "/*"
```

### Android app

Build the APK from `web/` with `VITE_API_BASE` set to `AppUrl`, then host it for download:

```bash
aws s3 cp app.apk s3://<WebBucketName>/download/app.apk --content-type application/vnd.android.package-archive
```

### Cooling points

```bash
AWS_DEFAULT_REGION=us-east-1 COOLING_TABLE=<CoolingTable> python scripts/seed_cooling_points.py
```
